## 贡献入口与范围

公开的 [picferry/picferry-website](https://github.com/picferry/picferry-website) 接受**网站、使用指南、翻译和样式**改进。欢迎修正错字、澄清操作步骤、补充经过核实的平台差异与安全边界。

GUI/Core 源码访问和公开发布状态以 [状态页](/status/) 的日期与核实范围为准。实现贡献需要先取得对应仓库访问权限，并遵循其协作约定。官网仓库的 **Releases 允许受控发布流程上传官方编译产物**，R2 保存同一份文件；PR 保持网站源码、文档和测试范围，二进制通过官方 Release 发布流程交付，不随 PR 提交。公开包下载与 GUI/Core 源码权限分别管理。

截至 2026-10-24，首个正式版本尚未发布。当前自动构建目标是 Linux x64、Windows x64 和 Android universal APK；[下载页](/download/) 在客户端校验实时清单后显示 R2 主下载、GitHub 备用、版本、大小和 SHA256，新增发布无需重建网站。

## 文档修改原则

- 中文在 `src/content/docs/`，英文在 `src/content/docs/en/`，对应文件名保持一致；同一能力变更同步更新两种语言。
- 中文站内链接使用 `/path/`，英文使用 `/en/path/`，保持读者所在语言。
- 将完整能力矩阵集中维护在 [状态页](/status/)，其他页面引用该页并补充各自的操作说明，避免多处重复状态表。
- 区分 GUI 入口、Core 实现、平台工程和公开发布；以实际验证结果表述能力，发布信息写明核实日期与范围。
- 保持现有页面设计和导航结构。纯文字修订聚焦事实与可读性，新增页面或样式调整单独说明目的。

## 本地预览与检查

以下命令的工作目录为 `picferry-website/`，需要与当前项目依赖兼容的 Node.js/npm 环境：

```sh
npm install
npm run dev
```

本地预览用于核对页面内容与布局，不会部署站点。纯文档修改可检查 frontmatter、内部链接、语言配对与 `git diff --check`；下载组件变更运行 `npm run build` 与 `npm test`，使用本地真实浏览器和测试清单验证双语页面及双下载链接，详见仓库 README。应用源码的分析、测试及原生环境准备见 [从源码构建](/install/)。

## 反馈与提交前核对

1. 描述平台、应用版本或源码修订、厂商、认证方式及可复现步骤；区分复制、迁移和图库显式删除。
2. 只附脱敏日志与截图，去除密码、验证码、Cookie、会话、账号/设备标识和签名媒体 URL。处理方式见 [安全](/security/)。
3. 检查 `git diff`，确认提交范围、中英文含义及链接一致，并列出实际执行的检查。
4. 对公开安装包或源码可访问性的报告，附上核实日期和公开入口；以观察到的事实为准，不推断未验证的发布计划。
